Contiguous Memory Concepts

Contiguous Memory Allocation Guide

Contiguous allocation gives each process one uninterrupted region of memory. When a process arrives, the OS searches the free blocks for a region large enough to hold it.

First Fit

Lowest Address Wins

Scan the memory blocks from the lowest address and allocate the first free block that is large enough. The search stops as soon as a match is found.

Trade-offs:
  • Pros: Simple, fast, and low overhead because the scan can stop immediately.
  • Cons: Tends to consume low-address memory first and can leave small, hard-to-use holes behind.

Best Fit

Smallest Adequate Hole

Examine every free block and choose the smallest block that can still hold the process. The leftover space is minimised for every individual request.

Trade-offs:
  • Pros: Usually leaves the largest possible holes for future requests; strong memory utilisation in the classic example.
  • Cons: Requires a full scan unless the free list is sorted; may create many tiny, unusable fragments.

Worst Fit

Largest Hole Wins

Choose the largest free block available. The idea is to leave a leftover region large enough to satisfy another process later.

Trade-offs:
  • Pros: Avoids tiny leftover holes and keeps one large free region available in some workloads.
  • Cons: Wastes large holes on small processes and often performs worse than First Fit or Best Fit.
Internal Fragmentation
Fixed Partitions

A process is placed in a partition larger than itself. The unused space inside that partition is wasted because it cannot be given to another process.

Internal waste = Partition size − Process size
External Fragmentation
Dynamic Partitions

Free memory exists in several separate holes. A waiting process may not fit even though the total free memory is large enough.

Scattered free = Total free − Largest free hole
Memory utilisation = Occupied memory / Total memory × 100 Preferred algorithm depends on workload and free-list organisation
