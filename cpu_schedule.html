OS Theoretical Concepts

CPU Scheduling Algorithms Guide

CPU scheduling is the foundation of multi-programmed operating systems. By switching the CPU among processes, the OS maximizes CPU utilization and interactive responsiveness.

1. First-Come, First-Served (FCFS)

Non-Preemptive

The simplest scheduling algorithm. Processes are allocated CPU cycles strictly in the order they arrive in the ready queue using a standard FIFO mechanism.

Key Characteristics:
  • Simple to implement with a FIFO queue.
  • Fair and starvation-free (every process is eventually serviced).
Disadvantages (The Convoy Effect):

If a CPU-bound process with a huge burst arrives first, all short I/O-bound processes must wait behind it, resulting in high Average Waiting Time.

2. Shortest Job First (SJF)

Non-Preemptive

Associates each process with its burst time. When the CPU becomes free, it dispatches the ready process with the smallest burst time.

Key Characteristics:
  • Provably Optimal for minimizing Average Waiting Time among non-preemptive algorithms.
  • Maximizes overall process throughput.
Disadvantages:

Requires knowing burst times in advance. Long processes may experience Starvation if short processes continuously arrive.

3. Shortest Remaining Time First (SRTF)

Preemptive SJF

The preemptive version of SJF. If a newly arrived process requires less remaining burst time than the currently executing process, the CPU preempts the running process.

Key Characteristics:
  • Provides the absolute lowest possible Average Waiting Time across all CPU schedulers.
  • Highly responsive to interactive, short-burst tasks.
Disadvantages:

Higher context-switching overhead and potential starvation for long CPU-bound tasks.

4. Priority Scheduling

Preemptive & Non-Preemptive

A priority rank is assigned to each process. The CPU is allocated to the process with the highest priority (configurable as lower integer or higher integer).

Key Characteristics:
  • Essential for real-time operating systems where critical tasks must execute immediately.
  • Can be combined with aging techniques to prevent indefinite postponement.
Disadvantages:

Low-priority processes may starve indefinitely under heavy load without an Aging mechanism.

5. Round Robin Scheduling (RR)

Preemptive Time-Sliced

Designed specifically for time-sharing systems. The CPU scheduler iterates around the ready queue, allocating the CPU to each process for a small time interval called a Time Quantum (TQ).

Key Characteristics:
  • Completely fair; every process receives an equal time slice of the CPU.
  • Superior Response Time (RT), ideal for interactive desktop and GUI operating systems.
  • Zero risk of starvation.
Impact of Time Quantum (TQ):

If TQ is too large, Round Robin degenerates into FCFS.
If TQ is too small, excessive context switches degrade system throughput. A standard guideline is that 80% of CPU bursts should be shorter than TQ.
