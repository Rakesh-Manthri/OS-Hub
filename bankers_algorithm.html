Deadlock Avoidance

Banker's Algorithm Guide

Banker's algorithm grants resources only when the resulting state is still safe. A state is safe if there exists at least one order in which every process can finish using the currently available resources plus resources released by earlier processes.

Safe State

At least one finish order

A safe state guarantees that some sequence of process completions can satisfy every outstanding need. The safe sequence is not necessarily unique.

Key idea:
  • Work starts as the current Available vector.
  • A process can finish when every Need entry is ≤ Work.
  • On finishing, it releases its Allocation back into Work.

Unsafe State

No finish order exists

If no unfinished process can fit within the current Work vector, the safety algorithm cannot make progress. The system is unsafe and may later deadlock.

Important:
  • Unsafe is not the same as deadlocked.
  • An unsafe state may never deadlock if processes behave well.
  • Banker's algorithm refuses every transition into an unsafe state.

Request Check

Three conditions

When a process asks for resources, Banker's algorithm checks the request against the announced maximum and current availability before pretending to allocate it.

Grant only if:
  • Request ≤ Need for every resource.
  • Request ≤ Available for every resource.
  • The hypothetical post-allocation state is safe.
