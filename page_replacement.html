Page Replacement Algorithms Guide

When a page fault occurs and no physical memory frame is free, the operating system must select an existing page in memory to replace with the newly requested page.

1. First-In, First-Out (FIFO)

Queue-Based Replacement

The OS maintains a queue of all pages currently in memory. When a replacement is needed, the page at the head of the queue (the oldest loaded page) is evicted.

Pros & Cons:
  • Pros: Extremely simple to implement using a FIFO queue. Minimal overhead.
  • Cons: Ignores how frequently or recently a page is accessed. Suffer from Belady's Anomaly (increasing frame count can sometimes increase page faults).

2. Least Recently Used (LRU)

Stack / Clock Based

Replaces the page that has not been accessed for the longest period of time. It relies on the principle of Temporal Locality of Reference.

Pros & Cons:
  • Pros: Highly effective in real-world workloads; immune to Belady's Anomaly (Stack Algorithm).
  • Cons: Requires hardware support (counters or stack) for fast lookup; high overhead if done purely in software.

3. Most Recently Used (MRU)

Inverse Locality

Replaces the page that was accessed most recently. Useful in scenarios where older pages are more likely to be re-used than recently accessed ones (e.g., cyclic file scanning).

Pros & Cons:
  • Pros: Ideal for sequential scans over large datasets exceeding frame capacity.
  • Cons: Poor performance for standard interactive workloads with strong temporal locality.

4. Optimal Page Replacement (OPT / MIN)

Theoretical Benchmark

Replaces the page that will not be used for the longest time in the future. Also known as Belady's Optimal Algorithm.

Pros & Cons:
  • Pros: Guarantees the absolute lowest possible page fault rate for a given frame capacity.
  • Cons: Impossible to implement in real OS kernel because it requires future knowledge of memory accesses. Used primarily as a theoretical benchmark.
